WHAT CHANGED SINCE V5 (all measured live, none changes a decision)
--------------------------------------------------------------------------
P0  Question state moved behind QUESTION_GATE.
    - live_audio.py no longer writes session state or the question field from a
      raw transcript. Single writer: QUESTION_ACCEPTED, after the gate.
    - App.tsx: question field is written only by QUESTION_ACCEPTED.
      TRANSCRIPT_CREATED is a listening/debug signal. An ignored utterance shows
      a transient status and never replaces the previous question.
    - Fixes: a STATEMENT ("Kindly enter your text here...") appearing under
      "السؤال".

P1  SELF_PLAYBACK_ACTIVE guard. Captured audio is dropped before STT while the
    app plays local audio (ws control message "self_playback", 400 ms cooldown).
    Preventive: the app ships no local playback today.

L1  Duplicate live bank lookup cancelled on the SHOW_ANSWER path.

L2  bank_guided_understanding.search_bank_candidates memoized on (raw, k),
    invalidated by question_bank.generation, plus a short-circuit so the
    difflib skeleton ratio is computed only when token overlap cannot already
    decide the gate. Root cause was 2386 difflib.SequenceMatcher.ratio() calls
    per lookup (75% of bank time), run 2-3x per question.
    Verified: 0 differing results over 49 queries (intent_id, combined,
    phonetic, lexical at 9 decimals). Cold scan 2.12x faster; repeat ~free.

L3  warm_start._warm_decode uses a real 6.6 s dev-pack clip (compound-dev,
    never a holdout pack) instead of 0.5 s of near-silence, which tripped
    no_speech_threshold and returned before the decoder loop ran.

L4  Stage timers at INFO: ANSWER_STAGES / ANSWER_TIMING / ANSWER_PUBLISH_MS.
    Measurement only. Keep them — they localised the bottleneck in one run.

Tooling: scripts\profile_live_answer.py, scripts\verify_bgu_equivalence.py.
